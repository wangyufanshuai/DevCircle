# 搜索业务版本与升级步骤

## 版本约定

事件信封的 `version: 1` 是 JSON 协议版本，不是内容业务版本。新增的 `payload.aggregateVersion` 来自 `post.version`，为非负 64 位整数，0 可用于升级前从未修改过的内容基线。

- 草稿修改、提交原本就递增 `post.version`；审核状态变更现在也在同一行更新中递增它。
- 审核事务把该版本及标题、摘要、分类、作者、标签、创建时间写入 Outbox。搜索不再收到稀疏事件后读取可能已经改变的公共详情。
- 内容侧的 `post.created/updated/deleted` 发布入口要求已有事务，在内容行锁下递增版本并读取权威快照。并发事件不能分配同一版本；回滚同时撤销版本变更和 Outbox。删除必须保留 `DELETED` 内容行，不能先物理删除再生成事件。
- 不以 `occurredAt`、事件 UUID 或 Outbox 自增 ID 推导业务顺序。不同文章的版本互不比较；版本允许有间隙。

MySQL 消费水位和 Elasticsearch 都只允许更高业务版本改写状态。同一 eventId 仍绑定原始载荷；相同业务版本的其他事件也不覆盖已有投影。删除是持久 `DELETED` 墓碑，保留业务版本，不是物理删除 ES 文档。重建索引使用相同的条件更新，不能绕过墓碑。

ES 条件检查通过 [官方 Update API 的脚本与 scripted upsert](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-update) 在文档更新时执行，旧版本设置 `ctx.op = 'noop'`。因此即使 ES 已写入而数据库完成记录失败，重试和较旧 worker 也不能回退较新投影。

## 升级必须显式切换

这是需要协调部署的搜索协议升级，不支持旧、新搜索写入器混跑。

先在隔离环境执行[本机迁移与回滚演练](search-migration-rehearsal.md)。通用 MySQL/MinIO 备份不能替代搜索快照和 Kafka 位点；恢复备份时点后必须先保持旧消费者关闭，避免切换期间的新消息再次改写旧索引。

1. 备份内容库、搜索消费状态、Kafka 位点及旧索引；暂停内容写入和审核，停止旧搜索消费者。记录切换窗口。
2. 部署新的内容、审核服务；确认已有内容迁移至 V23，`post.version` 可读取。新的内容列表响应必须携带 `aggregateVersion`。不要给历史消息批量伪造版本。
3. 部署新的搜索代码，执行搜索 Flyway V4。旧时间水位只保留审计用途，新增业务版本列保持 NULL，绝不从时间戳转换。搜索现在读写独立索引 **`devcircle-posts-v2`**，旧 `devcircle-posts` 保留作回滚证据，不直接复制到新索引。
4. 保持停写，以管理员身份经网关调用 `POST /api/search/admin/reindex`，用内容库当前已发布快照填充新索引。缺少业务版本的响应会失败。现有重建入口最多读取 100 页、每页 20 条；超过该规模须先扩展重建分页方案，不能声称已完整迁移。
5. 运行 `scripts/ops/verify-migration.sh`：比较数据库已发布数量与新索引 PUBLISHED 数量，允许 DELETED 墓碑，拒绝其他状态或缺失业务版本的文档。继续抽查内容 ID/标题/版本；计数相等不是逐条一致性证明。
6. 对遗留无版本事件保留审计记录并按 DLT 流程处理。新消费者明确拒绝这些事件；不要自动赋予“当前版本”后重放旧载荷，也不要清空墓碑或水位来强行通过。遗留内容以步骤 4 的权威基线恢复；切换后仅接受新生产者生成的版本事件。
7. 验证搜索可读、基线完整、DLT 已受控，然后恢复业务写入并观察 Outbox/消费积压。

回滚同样先停写和消费者。旧二进制使用旧索引，该索引不会包含切换后的所有更新；需要与备份位点和内容基线一起恢复，不能把旧二进制直接连到新索引继续写。本机演练入口与验收边界见[迁移演练说明](search-migration-rehearsal.md)；隔离本机结果不表示真实生产迁移已完成。

## 回归证据

`SearchCausalOrderIntegrationTest` 同时使用真实 MySQL、Flyway 和 Elasticsearch，覆盖：

- 同一毫秒、UUID 字典序反向，仍由业务版本确定胜者。
- 删除事件的时钟回拨、更新延迟到达、重复事件和同版本不同 ID 均不能复活旧内容。
- ES 水位领先数据库时，旧更新及旧重建快照不能覆盖墓碑；旧删除不能删除较新发布。
- 过期 worker 延迟写入被 ES 版本条件阻止，旧租约也不能完成新处理者的数据库状态。
- 缺失、负数、小数、溢出和字符串版本在产生副作用前被拒绝。

`DraftPersistenceIntegrationTest` 验证 8 个并发事务的唯一递增版本、权威内容快照以及版本/Outbox 原子回滚；`AdminServiceStateTest` 验证审核事件版本与已提交状态一致，幂等重试不增发。`SearchLeaseIntegrationTest` 保留真实 MySQL 租约竞争与失效隔离反例。

仍需保留墓碑并限制所有写入通道。直接手工覆盖 ES、物理清除墓碑、复用已删除内容 ID 或旧代码绕过版本写入，都超出这些保证。当前重建是版本安全的已发布快照更新，不是自动修复任意数据损坏的工具。
