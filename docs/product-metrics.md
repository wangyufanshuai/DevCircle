# MysticVerse 产品指标口径

## 目标与原则

首版北极星指标为 **每周有效阅读解谜用户数（WMRU）**：自然周内至少完成一次有效阅读或解谜行为的去重登录用户。有效行为满足任一条件：正文进度达到 50%、提交一次答案、完成一次解谜、收藏内容或发布一条可见评论。

所有指标使用服务端持久化数据计算，不依赖浏览器自报成功。重复幂等请求、管理员测试账号、开发 seed 操作和已删除的压测账号必须排除。日报使用 Asia/Shanghai 自然日，留存以首次注册日 cohort 计算；原始事件保留 UTC 时间。

## 核心漏斗

| 指标 | 口径 | 权威数据源 | 首版观察线 |
| --- | --- | --- | --- |
| 注册成功用户 | `user_account.created_at` 去重账号 | Auth `user_account` | 只报告趋势，不设虚假增长目标 |
| 24小时激活率 | 注册后24小时内达到一次有效阅读或解谜 / 注册成功用户 | `user_account` + `reading_progress` + `deduction_attempt` | ≥ 35% |
| 详情到尝试率 | 有解谜资格的详情去重读者中，提交答案的用户占比 | `recommend_event_log` + `deduction_attempt` | ≥ 25% |
| 解谜正确率 | 首次答题正确用户 / 首次答题用户；主动揭示者不计正确 | `deduction_attempt` + 解谜状态 | 仅按难度分层观察 |
| 继续阅读完成率 | 进入继续阅读轨道后7天内完成内容 / 进入轨道用户 | `reading_progress` | ≥ 30% |
| 收藏率 | 收藏成功的详情会话 / 可收藏详情会话 | Interaction + `recommend_event_log` | ≥ 8% |
| 关注转化率 | 详情作者区产生关注 / 登录详情读者 | User Follow + `recommend_event_log` | ≥ 5% |
| 草稿投稿率 | 7天内提交审核的草稿作者 / 新建草稿作者 | `post` 状态时间线 | ≥ 40% |
| 投稿发布率 | 发布投稿 / 已完成审核投稿 | `post_audit_record` | ≥ 70%；必须同时观察驳回原因 |
| 审核中位时长 | `PENDING` 到首次人工决定的 P50/P95 | `post_audit_record`、`moderation_task` | P50 < 12h，P95 < 48h |

## 发现与推荐

| 指标 | 口径 | 数据源 |
| --- | --- | --- |
| 推荐曝光去重率 | 重复曝光记录 / 全部曝光请求；相同幂等键只计一次 | `recommendation_impression` |
| 推荐点击率 | 推荐详情点击用户 / 推荐曝光用户 | `recommend_event_log` + `recommendation_impression` |
| 主题探索占比 | 探索召回曝光 / 全部推荐曝光 | 推荐特征与 `recallSources` 日志 |
| 搜索无结果率 | 返回0条的有效搜索 / 全部有效搜索 | Gateway 搜索请求指标 + Search 结果事件 |
| 搜索到详情率 | 搜索后30分钟内打开结果详情的用户 / 搜索用户 | `recommend_event_log`，按 trace/session 关联 |

推荐指标必须按 `experimentId`、`bucket`、主题和新老用户分层。没有达到最小样本量前只展示计数与置信区间，不宣称实验胜出；不得使用同一用户的重复曝光放大样本量。

## 留存与健康度

- D1/D7 留存：注册用户在第1/7个自然日再次产生有效阅读、解谜、互动或创作行为。
- WAU/MAU：至少一次有效行为的去重登录用户；匿名浏览单独统计，不混入社区留存。
- 创作者周留存：本周有草稿/投稿行为的作者，下周再次创作或修改投稿。
- 通知回访率：通知送达后24小时内打开有效目标的去重接收者；目标已失效不进入分母。
- 用户可见失败率：产生公开错误码且未在同一会话重试成功的用户操作 / 全部用户操作，按 `traceId` 去重。

## 数据质量门禁

1. 所有写入指标使用业务表或幂等事件，不从 HTTP 2xx 数量推断成功。
2. 答题、揭示、点赞、收藏、关注、评论、曝光和已读必须按业务唯一键去重。
3. 数据源不可用时仪表盘返回不完整状态和缺失来源，禁止用零值补齐。
4. 每日任务记录查询窗口、代码 SHA、行数、生成时间和校验和；补数使用同一口径版本。
5. 指标定义变更必须增加版本与生效日期，不回写历史口径伪造连续趋势。
6. 对外报告只使用聚合结果；邮箱、OAuth ID、答案文本、评论正文和媒体对象键不得进入分析导出。

## 首版报表节奏

- 每日：注册、激活、有效阅读、答题、发布、用户可见失败和审核积压。
- 每周：WMRU、D1/D7、频道结构、推荐/搜索漏斗、创作者漏斗和内容治理原因。
- 每月：SLO、错误预算、恢复演练、内容供给、用户留存和实验决策复盘。

## 当前埋点边界

现有业务表已经能可靠计算注册、阅读进度、答题/揭示、收藏、关注、草稿/投稿、审核、推荐曝光和推荐事件。搜索结果数量、匿名会话、通知实际送达/打开和跨页面 session 关联尚缺统一服务端事件；对应指标在补齐事件 schema、幂等键和保留策略前必须显示“数据源未完成”，不得用前端点击数或零值代替。

在目标 Linux 环境和真实用户试运行前，本文中的观察线只是产品假设，不是已达成结果。
