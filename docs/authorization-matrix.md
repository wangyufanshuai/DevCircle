# 权限与拒绝副作用矩阵

交付包 2 的验收以“角色 × 资源归属 × 业务状态 × 操作”定义；HTTP 拒绝只是第一步，还要检查数据库、Outbox、积分及幂等记录没有被错误修改。下表区分已有测试入口和仍需补齐的真实链路，不把存在测试文件等同本轮执行通过。

| 资源/操作 | 必须成立的边界 | 现有入口 | 后续验收缺口 |
|---|---|---|---|
| 网关身份 | 匿名写入拒绝；访问令牌校验；覆盖伪造的 `X-User-Id` 和 `X-Roles`；读者不得访问管理接口 | `AccessTokenFilterTest`、核心 HTTP 验收 | 过期/刷新令牌、封禁及禁言账号的真实请求矩阵 |
| 草稿读取/编辑 | 其他账号拒绝；旧业务版本不能覆盖新版本；拒绝不得改内容或增加事件 | `DraftPersistenceIntegrationTest`、核心 HTTP 验收 | 审核中、驳回、删除等状态与角色交叉验证 |
| 解谜答案/积分 | 未获得权限时不返回解析；同用户同题一次积分；换用户/载荷复用幂等键拒绝 | `DeductionConcurrencyIntegrationTest`、两轮核心验收 | 真正执行中的进程故障及恢复 |
| 媒体完成/公开读取 | 他人不能确认上传；公开访问必须同时满足上传完成、审核通过、关联已发布内容 | `MediaRepositoryStateTest`、`FileUploadIntegrationTest`、核心 HTTP 验收 | 已公开后下架/删除撤销访问、单条与批量一致、签名过期的真实对象存储反例 |
| 评论删除/隐藏/读取 | 作者只能删除自己评论；审核权限与普通删除分离；隐藏文本不泄露给读者；事件与审计不得重复 | `CommentRepositoryStateTest`、`CommentServiceTest`、`PostCommentControllerTest` | 通过真实网关覆盖跨用户删除、伪造审核身份和隐藏后读取 |
| 通知列表/未读数 | 只返回令牌所属账号的通知；伪造身份头无效；ADMIN 不自动获得他人收件箱 | `NotificationRepositoryStateTest`；新增 `check_notification_permissions` 核心 HTTP 验收 | 本轮新增真实链路，结果单独归档 |
| 通知已读/全部已读 | 匿名拒绝；跨收件人拒绝且不消耗幂等键；同键不能跨用户、操作；重复全部已读不能吞掉后来到达的通知 | 同上，真实 Kafka 生成夹具，HTTP 操作后查询数据库，第二轮重启复核四条通知 | 并发标记和实时会话失效另验 |
| 通知 WebSocket | 认证 CONNECT；只允许本人队列；禁止客户 SEND；到期会话退出 | `NotificationStompChannelInterceptorTest`、`NotificationWebSocketSessionRegistryTest` | 将真实跨会话/过期反例与 HTTP 矩阵统一记录 |
| 关注/互动与个人数据 | 私有状态由当前身份派生；幂等键绑定用户和载荷；重复/乱序消费不回退状态 | `UserGraphFollowStateTest`、社区 E2E、投影集成测试 | 多资源跨用户请求及真实进程中断后无重复通知/积分 |
| 搜索重建管理 | 匿名 401、读者 403；拒绝不得创建或推进任务；管理员执行受互斥和持久 revision 保护 | V5 真实迁移演练、`SearchReindexJobsTest` | 中途进程退出与消费者租约重放验收见下文 |
| 内部运维入口 | 不从公共网关路由；运维密钥不进入日志；领域服务不能直接暴露到公网 | 生产编排、内部运维鉴权与路由测试 | 干净环境实际端口与网络边界验收属于交付包 5 |

## 真实故障的完成条件

必须观察到消费任务正在执行后再终止进程。仅在两个已确认批次之间重启，不能证明批次内崩溃恢复。

1. 在隔离项目中让真实消费者取得租约，阻断其外部投影依赖；数据库能看到未完成租约，Kafka 消费位点尚未确认该事件。
2. 终止该消费者进程，保留数据库、Kafka 和索引；恢复依赖并重启消费者。
3. 等待真实租约到期和消息重投，不直接修改租约时间或消费位点来伪造成功。
4. 最终事件只产生一份业务结果，持久租约完成，位点前进；旧事件再次投递及旧业务版本均不能回退状态。
5. 记录注入点、前后数据库/索引/位点和资源结果。失败保留证据，禁止自动清空数据让测试变绿。

## 本机执行约束

搜索消费者的上述故障闭环已在独立 Search 和生产 Discovery 进程中完成；旧镜像失败、新镜像成功的[具体证据](evidence/2026-10-14-search-consumer-crash.md)单独保留。此结果不替代其他消费者及权限矩阵中的剩余项目。

核心切片、社区切片与搜索故障切片串行运行。数据、缓存和证据留在 D/E 盘；检查磁盘和内存储备，只操作本次所属 Compose 项目。核心入口为 `python scripts/dev/local.py verify`，仍执行两轮重启并保留既有测试数据。此矩阵不宣称全域权限或生产安全已经验收完毕。
